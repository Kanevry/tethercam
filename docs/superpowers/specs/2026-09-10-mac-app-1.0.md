# TetherCam for Mac 1.0

Date: 2026-09-10. Status: proposed (GitLab issue #20). Corrections are appended dated at
the end, nothing above is rewritten. Builds on
[2026-09-09-virtual-camera-cmio.md](2026-09-09-virtual-camera-cmio.md) (the design that
shipped as 0.2.1) and does not touch the wire format except for one optional message
(see 1.0 scope, CLIENT_INFO). Ground truth for everything below: `mac-app/App/*.swift`,
`mac-app/Core/Sources/TetherCamCore/`, `mac-app/project.yml` (MARKETING_VERSION 0.2.1,
CURRENT_PROJECT_VERSION 6), `scripts/mac-app-release.sh`, `.github/workflows/`.

## Product framing

**The Mac app is the default path.** "iPhone as a wired webcam in every Mac app" is what
almost everyone wants: Zoom, Teams, Meet, FaceTime, QuickTime, Safari, Chrome. It needs
no OBS, no plugin install, no scene setup.

**The OBS plugin is the pro path.** It stays the lowest-latency route, it is the only one
that carries **audio** (a CMIO camera extension cannot), and it is the one that belongs
in a streaming scene. Neither replaces the other; the phone serves **one receiver at a
time**, so running both yields BUSY for the second (`LinkState.busy`).

Consequence for the website and README ordering: lead with the .dmg, keep the plugin as
"for OBS streamers".

## Journey: today vs 1.0

Today (0.2.1, verified 2026-09-09):

1. Download `TetherCam-mac.dmg` from the GitHub release (or `brew install --cask tethercam`).
2. Drag the app into `/Applications` **with Finder** (any other copy triggers App
   Translocation and the app reports "must be in /Applications" although it is there).
3. Open it — menu-bar only, no window, no explanation of what happens next.
4. macOS asks once for the camera extension: System Settings > General > Login Items &
   Extensions > Camera Extensions > enable TetherCam (**admin password**). The menu has a
   button that opens the pane; nothing tells the user this is coming.
5. Open TetherCam on the iPhone and keep it in the **foreground** (iOS suspends the
   listener otherwise) — documented in the README, invisible in the app.
6. Pick the camera "TetherCam" in the target app. Apps read camera lists at launch, so an
   app started before the extension appeared must be quit and reopened.

Target (1.0): steps 1, 2, 6 unchanged (they are macOS-imposed); steps 3-5 are carried by a
first-run window that states the approval, the foreground rule and the two limits before
the user hits them.

## 1.0 scope

Each item lists its acceptance criterion (AC).

1. **First-run / onboarding window** (new `App/OnboardingView.swift`, state in `AppState`).
   Content: the four steps with the approval click path; "the TetherCam app on the iPhone
   must stay in the foreground"; "the virtual camera carries **no audio** — use the OBS
   plugin for that"; "do not run it together with the OBS TetherCam source, the phone
   serves one receiver at a time (BUSY)".
   AC: shown on first launch and via a "Show setup guide" menu item; a `didCompleteSetup`
   flag in `UserDefaults` suppresses it afterwards; the approval button routes to the
   existing `ExtensionInstaller.openSystemSettings()`; the window is reachable while the
   extension state is `.waitingForUser`.
2. **App icon and a designed DMG.** Today the .dmg is a plain volume with the app in it.
   AC: `Assets.xcassets` app icon at all required sizes; the .dmg carries a background
   image with an arrow to the Applications alias and a fixed window/icon layout, produced
   reproducibly by `scripts/mac-app-release.sh` (no manual Finder step).
3. **About / version in the menu.** AC: a menu row reads
   `TetherCam <MARKETING_VERSION> (<CURRENT_PROJECT_VERSION>)` from the bundle, plus a
   link to https://tethercam.app; copy-to-clipboard for a bug-report string that includes
   the version, macOS build and the current `PipelineStatus.line`.
4. **Launch at Login** via `SMAppService.mainApp`. AC: a menu toggle whose state reflects
   `SMAppService.mainApp.status`; enabling registers, disabling unregisters; the failure
   path (user denied it in System Settings > General > Login Items) shows a sentence, not
   a thrown error.
5. **Uninstall.** `ExtensionInstaller.deactivate()` exists (`Camera/ExtensionInstaller.swift:47`)
   and has no caller. AC: a "Remove camera extension…" menu item with a confirmation
   sheet; it stops the pipeline, submits the deactivation request, reports the resulting
   state, and tells the user to drag the app to the Trash afterwards; running
   `systemextensionsctl list` then shows no TetherCam entry.
6. **CLIENT_INFO, protocol 1.2.** New optional message `0x04`, Mac → App, sent after HELLO
   and before START: `kind` (u8; 1 = OBS plugin, 2 = Mac app), `name` string
   ("TetherCam for Mac"), `version` string. The phone may then name the connected
   receiver in its UI ("TetherCam for Mac 1.0" instead of "a Mac"). Backwards compatible
   by §4.1's forward-tolerance rule: a 1.0/1.1 app skips an unknown type by `length`.
   AC: `protocol/PROTOCOL.md` bumped to 1.2 and changed **first**; both Swift senders and
   the iOS parser follow; a 1.1 iOS build still streams unchanged against a 1.2 Mac app
   (regression test in `tools/`).
7. **CI for mac-app.** `.github/workflows/` has `ci-plugin.yml`, `release-plugin.yml`,
   `testflight-ios.yml` and nothing for the Mac app. AC: `ci-mac-app.yml` runs
   `swift test --package-path mac-app/Core` and an unsigned
   `xcodebuild -scheme TetherCam ... CODE_SIGNING_ALLOWED=NO` build on every push touching
   `mac-app/**`, `shared/**` or `protocol/**`; red build blocks the merge.
8. **Honest counters (#16).** Done ahead of 1.0 (see the 2026-09-10 correction in the CMIO
   spec): scaler drops counted, `noConsumer` derived, raw counters behind the debug flags,
   real sink queue capacity surfaced. AC for 1.0: the menu never shows a raw drop count in
   the normal path.
9. **Zoom and Teams verification (#13).** Both are still untested (only Meet, FaceTime,
   QuickTime, Photo Booth, Safari, Chrome and ffmpeg were). AC: a real-device run with
   Zoom and Teams, result recorded in #13 and in the compatibility list of
   `mac-app/README.md`.

## Explicitly deferred (with reasons)

- **Sparkle / update check.** The cask and the GitHub release already update users who
  installed via Homebrew; adding an updater means a second signing surface and an
  appcast to host. Revisit when non-Homebrew installs dominate.
- **Sink authorization (Open Risk 5).** Any local process may open the extension's sink
  stream and feed it frames; the extension does not check its client. `StreamSink` already
  logs `client.pid`/`signingID`, so a team-ID check is possible — but a wrong check
  bricks the camera for the legitimate host, and the attack requires local code execution
  that already has camera access. Deferred, not forgotten.
- **Receiver/transport duplication.** Three receivers now exist: `mac-app/Core` (Swift),
  `tools/usbcam-recv` (Swift) and the C/ObjC++ OBS plugin. Unifying them is a refactor
  with no user-visible effect and real regression risk on the plugin's audio path;
  `shared/` stays the shared C floor.
- **Audio to a virtual microphone.** Would need a separate audio driver (Core Audio
  server plugin / AudioServerPlugIn), its own approval and its own sync story. The OBS
  path covers audio today.
- **Mac App Store (#15/#17).** Blocked, not postponed: `cmioextension.sb` denies usbmuxd
  unconditionally for the extension, and the App Sandbox denies it for the host
  (`docs/mac-app-store-feasibility.md`).

## Decisions to make before 1.0

1. **Version coupling.** Today one `v*` tag drives the iOS app, the OBS plugin .pkg and
   the Mac .dmg, and `mac-app/project.yml` carries its own MARKETING_VERSION (0.2.1) —
   so "TetherCam 1.0" would silently promise a 1.0 iOS app and a 1.0 plugin too.
   Option A: keep one tag, ship all three at 1.0. Option B: a separate `mac-v*` tag with
   its own release job, decoupling the three product lines.
   Recommendation: **B** — the Mac app is the youngest artefact and will iterate fastest.
2. **CFBundleVersion bump rule.** `sysextd` replaces an installed extension only when the
   new bundle carries a **higher build number**; a rebuilt .dmg with the same
   CURRENT_PROJECT_VERSION installs the app but keeps the OLD extension running, which is
   the nastiest possible silent failure. Rule to write down and enforce in
   `scripts/mac-app-release.sh`: every release bumps CURRENT_PROJECT_VERSION, and the
   script refuses to package a version whose build number already exists on a release.
3. **Naming.** The camera keeps the name **"TetherCam"** (`TetherCamContract`). It is what
   users are told to look for in every app, in the README, on the website and in the store
   listing; renaming it would break every existing setup for zero gain.

## Out of scope for this spec

The iOS app, the OBS plugin and the website. 1.0 changes nothing about the phone side
except the optional CLIENT_INFO handling in item 6.
